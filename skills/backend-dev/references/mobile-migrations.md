# Mobile migrations: Supabase SQL and Drizzle/expo-sqlite

**Trigger:** these rules are keyed on the migration tool (Supabase SQL in `supabase/migrations/`, Drizzle in `drizzle/`), not on `feature.json.platform`. They apply to web projects using Supabase too. The "any older shipped app version" check applies only where a native client exists: Drizzle/expo-sqlite bundled in the app (and server migrations read by shipped mobile clients); it is vacuous for a web-only project.

Both tools are **forward-only**: there are no `down` files. Replace the reversibility check with the checks below.

## Reversibility exception

A missing `down` is acceptable (not a BLOCKER) for Supabase SQL migrations and Drizzle/expo-sqlite migrations. Other tools keep `references/reversibility-checks.md`.

## Compatibility check (shipped app versions)

Mobile binaries stay installed for months, so the schema must work for every app version still in the field.

- BLOCK when a server (Supabase) migration breaks an already-shipped app version: dropping or renaming a column, tightening a constraint, or changing a type that older clients read or write. Require expand/contract: add the new shape, ship the app, backfill, and drop the old shape only after old versions are retired. See `references/zero-downtime-patterns.md`.
- BLOCK when the on-device Drizzle chain cannot apply cleanly from any older shipped version. The chain is `drizzle/migrations.js` (generated by `npx drizzle-kit generate`) applied at launch by `useMigrations(db, migrations)` from `drizzle-orm/expo-sqlite/migrator`. Never edit or reorder an already-shipped migration; only append new ones. Check that each step works on data left by the oldest supported version.

## RLS check (Supabase)

Every new table in the `public` schema must have both:

- `alter table ... enable row level security;`
- at least one `create policy ...`

Otherwise BLOCK: with the `anon` key, a table without RLS is world-readable. RLS policies are the authz layer here.

Optional tooling: `supabase db lint` or the Security Advisor rule `rls_disabled_in_public` can flag this.

## Delegation

If `expo:*` skills are available, invoke `expo:expo-overview` first, then `expo:expo-data-fetching` for the client data layer. If they are not installed, see https://docs.expo.dev/ and https://orm.drizzle.team/docs/connect-expo-sqlite; minimum commands: `npx drizzle-kit generate`, then `supabase db lint`.
